Manifest format (schema 1) ​

A manifest describes one package (a runtime, service or tool) with every version's download fully resolved: exact URL and SHA-256 per platform. Tiffin never builds URLs from templates on the client; generators in the registry repo do that, and the signed index covers every byte (ADR 0008).

Check manifests with:

bash
tiffin registry validate path/to/manifests

Print the JSON Schema (point your editor at it for completion):

bash
tiffin registry schema > manifest.schema.json

Example ​

json
{
  "schema": 1,
  "name": "node",
  "type": "runtime",
  "description": "JavaScript runtime",
  "homepage": "https://nodejs.org",
  "bins": [
    {"name": "node", "path": "bin/node"},
    {"name": "npm", "path": "bin/npm"}
  ],
  "versions": [
    {
      "version": "22.11.0",
      "assets": {
        "linux-amd64": {
          "url": "https://nodejs.org/dist/v22.11.0/node-v22.11.0-linux-x64.tar.xz",
          "sha256": "<64 lowercase hex characters from SHASUMS256.txt>",
          "format": "tar.xz",
          "strip": 1
        },
        "windows-amd64": {
          "url": "https://nodejs.org/dist/v22.11.0/node-v22.11.0-win-x64.zip",
          "sha256": "<...>",
          "format": "zip",
          "strip": 1,
          "bins": [
            {"name": "node", "path": "node.exe"},
            {"name": "npm", "path": "node.exe", "args": ["node_modules/npm/bin/npm-cli.js"]}
          ]
        }
      }
    }
  ]
}

Fields ​

FieldRequiredRules
schemayes1
nameyes1-40 of a-z 0-9 -, starts with a letter or digit
typeyesruntime, service or tool
descriptionyesnot empty
homepagenohttps URL
binsruntimes/tools*default executables, see below
versionsyesat least one; versions must be unique
serviceservices onlyhow tiffind runs it, see Services

* Every runtime and tool asset must end up with at least one bin, from the manifest or from the asset itself.

Version: 1-4 numbers without leading zeros, optional -pre.release and +build: 8.4.1, 16.4, 7, 21.0.5+11, 1.2.3-rc.1. Versions compare numerically (1.0 equals 1.0.0); a pre-release sorts before its release; the build number breaks ties (21.0.5+11 > 21.0.5+9).

Assets are keyed by platform: linux-amd64, linux-arm64, darwin-amd64, darwin-arm64, windows-amd64, windows-arm64. Leave out platforms with no official build; never guess a URL.

Asset fieldRequiredRules
urlyeshttps, with a host, no credentials
sha256yes64 lowercase hex characters, from the vendor's checksum file
formatyeszip, tar.gz, tar.xz, tar.zst, or raw (the download is the binary)
stripnoleading path components to drop, 0-5 (raw: 0)
sizenobytes, for progress bars
binsnoreplaces the manifest's bins on this platform
extrasnoup to 4 more archives (url, sha256, format other than raw, strip, size, inner, keep, dir) extracted into the same folder, or into dir inside it (a clean relative path, no Windows device names: Windows PHP's Xdebug and pcov, ADR 0084); files may not overlap, unless keep is true: then the files the folder already has stay and only new ones are added
innerno{path, format}: an archive inside the download (a clean relative path; an archive format, not raw), extracted instead of it, with strip; the download's sha256 covers it. Not for raw downloads
setupno{path, args}: a program of the package's own (a clean relative path) run once in the version folder after unpacking, as the user, before the bins are checked; up to 4 args, each plain text or {dir} (the version folder's absolute path). For upstreams that must be told where they live (hex.pm's Erlang: Install -minimal {dir}, ADR 0086). Not for raw downloads

Bins: name is the shim name ([A-Za-z0-9][A-Za-z0-9._+-]*, not ending in ., unique ignoring case, since Windows and macOS filesystems ignore case, and not a Windows device name such as nul or com1, even with an extension). path is relative to the install directory, /-separated, clean, with no .., : or \. On Windows it must end in .exe; elsewhere it must not end in .exe. .cmd and .bat wrappers are refused, because cmd.exe re-parses their arguments and a crafted argument could run commands; run the interpreter instead, with args: up to 4 files in the package (same path rules) passed before the user's arguments, e.g. node.exe node_modules/npm/bin/npm-cli.js. (The shim never runs a batch file; programs the tool starts can still find the package's own wrappers on PATH, see ADR 0013.) via names another package whose bin of that name runs path: {"name": "composer", "path": "composer.phar", "via": "php"} runs the PHP chosen for the current folder with composer.phar (ADR 0016). A via bin's path need not be executable or an .exe; via and args do not mix. A raw asset has exactly one bin.

Services ​

A service package also says how tiffind runs it (ADR 0028). Commands name one of the package's bins, found per platform like any bin, and run without a shell. An init, run or stop command can't use a via bin.

json
"service": {
  "port": 5432,
  "data_dir": {"per": "major"},
  "configs": [{"name": "postgresql.conf", "template": "listen_addresses = '127.0.0.1'\nport = {{port}}\n..."}],
  "init": {"bin": "initdb", "args": ["-D", "{{data_dir}}", "--auth=trust", "-U", "postgres", "-E", "UTF8"], "marker": "PG_VERSION"},
  "run": {"bin": "postgres", "args": ["-D", "{{data_dir}}", "-c", "config_file={{conf_dir}}/postgresql.conf"]},
  "health": {"probe": "postgres", "timeout": 60},
  "stop": {"signal": "interrupt", "grace": 10,
           "command": {"bin": "pg_ctl", "args": ["stop", "-D", "{{data_dir}}", "-m", "fast", "-w"]}},
  "windows": {"init": {}, "run": {}, "stop": {}}
}
FieldRequiredRules
portyesdefault port, 1024-65535 (no elevation needed); the user can change it per project
data_dir.peryesshared (every version uses one folder), major (16.x) or minor (8.4.x): versions with the same key share their data
configsnoup to 4 {name, template}, written into the configuration folder before every start (changes are overwritten; templates should include a folder for the user's own settings). name is a plain lowercase file name; a template is at most 16 KB
initnocommand (bin, args, env) that sets up a new data folder; it runs while marker (a path relative to the data folder) does not exist
runyesthe server, in the foreground
health.probeyestcp, postgres, mysql or redis: how tiffind tells it is ready
health.timeoutyesseconds to become ready, 1-300
stop.signalyesterm, interrupt or quit, used where signals exist
stop.graceyesseconds before tiffind kills it, 1-120
stop.commandWindowsthe graceful stop where there are no signals (pg_ctl stop -m fast, mariadb-admin shutdown); required when the package has a Windows asset, unless kill_safe
settingsnowhere tiffin service set writes the user's settings (ADR 0078): file (in the instance's conf.d, which a config must include), header (a first line such as [mysqld]), line (one setting, with {{key}} and {{value}} once each) and reserved (keys Tiffin sets itself; - and _ count as one)
stop.kill_safenotrue when a kill loses nothing (no data, or a crash-safe store such as LMDB); then Windows needs no stop.command
windowsnoreplaces init, run or stop as a whole on Windows
dbnolist, create, drop, backup, restore: commands for tiffin db (ADR 0033); list prints one database name per line, backup writes SQL to stdout, restore reads it from stdin; they may also use {{database}}

A command has bin, up to 32 args (512 bytes each) and up to 8 env variables ([A-Z_][A-Z0-9_]*). Arguments, environment values and templates may use these placeholders, replaced as plain text:

PlaceholderValue
{{port}}the port in use
{{data_dir}}the data folder (during init, the folder being set up)
{{conf_dir}}the configuration folder
{{log_dir}}the log folder
{{run_dir}}a short private folder for sockets and pid files
{{install_dir}}the version's install folder
{{version}}, {{version_major}}16.4, 16
{{database}}in db commands only: the database name (checked by tiffind: [a-z][a-z0-9_]*, at most 63)

Any other {{...}} is an error. In configuration files folders use / on every OS: MySQL, PostgreSQL and Redis read \ as an escape, and all accept / on Windows. In arguments, folders use the OS's own separator. Folders are paths, so quote them in a template (datadir = "{{data_dir}}") because they may contain spaces. tiffind refuses to start a service whose folders contain a quote, a newline or NUL. Services listen on 127.0.0.1 only: that is the template's job.

Strict vs lenient ​

tiffin registry validate is strict: unknown fields are errors (usually typos). Clients installing packages are lenient about unknown fields only, so a newer registry can add optional fields; every other rule still applies. A higher schema number tells older clients to update.
