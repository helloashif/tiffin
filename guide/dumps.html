Dumps and queries ​

With Tiffin's Laravel package installed, every dump() and dd(), every database query and each request's summary appear in Tiffin, beside your site, with warnings for N+1, duplicate and slow queries.

bash
composer require --dev tiffin/laravel

That's all: sites Tiffin serves send to it already. Then open Dumps in the app (its Set up… button has these steps, and the line for .env that commands run in a terminal need), or:

bash
tiffin dumps               # recent requests, with their warnings
tiffin dumps show <id>     # one request's dumps and queries, in order
tiffin dumps --follow      # as they happen
tiffin dumps --site shop   # one site's
tiffin dumps clear

Choosing what is kept ​

Tiffin keeps three things of a request, each of which you can switch off: dumps, queries (and so their warnings) and requests (every site's requests as they arrived, with headers, cookies and body, to send again). In the app it is Capture on the Dumps screen, or:

bash
tiffin dumps capture                # what is on
tiffin dumps capture queries off    # for what arrives next
tiffin dumps capture queries on

A change applies at once and is remembered. What is already kept stays until you clear it.

Any site's requests ​

Every PHP request Tiffin serves is listed too, from any site: WordPress, Symfony, plain PHP, or a Laravel app without the package. Each shows its method and address, the status and how long it took, and can be sent again or copied as curl (below). Only the package adds dumps and queries.

Sending a request again ​

Tiffin's proxy keeps each of the newest 50 PHP requests as it arrived: method, address, headers (cookies too) and a body of up to 256 KB. Each request on Dumps shows it, and can be sent again, with the same session and form fields, as often as you like while you change the code:

bash
tiffin dumps replay <id>   # send it again; its dumps arrive as a new request
tiffin dumps curl <id>     # the same request as a curl command

In the app, a request on Dumps has the request it came from, with Replay, Replay with profiler and Copy as curl. A request Xdebug profiled has a Profile tab too (see Xdebug and pcov).

  • A replay goes through Tiffin itself, as the original did, so it hits the same site, PHP and settings. A form post replays fine while its session is valid.
  • A body over 256 KB (a file upload, say) isn't kept, so that request can't be sent again.
  • Requests from visitors through tiffin share are never kept.
  • The kept requests hold cookies and form fields: they stay in memory and go with tiffin dumps clear or when tiffind stops.

The package files its dumps under the proxy's id, so an older tiffin/laravel has to be updated first: composer update tiffin/laravel.

The warnings ​

For each request:

  • N+1: the same query (literals and IN lists aside) from the same line of your code, run 5 or more times.
  • Duplicate: the very same query with the same bindings, run twice or more.
  • Slow: one query of 100 ms or more.

Queries Laravel runs itself (with no line of your code in their stack), such as reading the session, are only checked for slowness.

Safe to leave installed ​

  • It does nothing unless APP_ENV=local.
  • Events are sent once, at the end of the request, to tiffind on 127.0.0.1. If Tiffin doesn't answer within 50 ms the package stays quiet; your page is never slowed or changed.
  • Tiffin keeps the newest 50 requests, in memory only.

Settings ​

Optional, in .env:

dotenv
TIFFIN_ENABLED=false             # turn it off without removing it
TIFFIN_DUMPS_ADDR=127.0.0.1:9913 # where tiffind listens (the default)

Set TIFFIN_DUMPS_ADDR when you run the app another way, such as php artisan serve, and have moved tiffind's port.

Requirements: PHP 8.1+, Laravel 10 to 13.
