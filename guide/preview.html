AI preview ​

Pick an element on one of your sites and let your own coding agent find the code behind it. Tiffin holds the pick; your agent reads it. Tiffin does not run an agent, hold a key for one or change your files.

How it goes:

  1. You pick an element in the Preview window of a project.
  2. tiffind holds the pick in memory.
  3. Your agent pulls it: it calls the preview_selection MCP tool, or you press Copy prompt and paste the prompt into the agent.
  4. The agent edits your files with its own tools.
  5. You read the result in the Changes tab or with tiffin diff: a read-only git diff.

Pick an element in the app ​

Open a project in the Tiffin app and choose Preview. A second window opens on the site's .test address. Press Pick element in the corner, move over the page, and click what you want changed. The pick goes to tiffind; your agent reads it with the commands below. A pick from a workspace host (feat-x.shop.test) names the workspace.

  • The picker runs only in this window, and only on .test names that Tiffin serves. If you go to another site in the window, the picker does nothing.
  • It makes no network calls and changes nothing in your site or in Tiffin's proxy. A click your page's own scripts make is ignored: only your real click picks.
  • It sends the selector, the element's text, its trimmed HTML (scripts, event handlers and form values are removed) and the page URL. It does not guess source files.
  • To hand the pick over, the picker puts it on your clipboard for a moment and Tiffin puts your old clipboard text back.
  • macOS only for now. On Windows and Linux the button is Copy selector: it copies the CSS selector and sends nothing to Tiffin. Picking there waits for a check on those systems.
  • The route is filled in for sites whose routes Tiffin can read from files (OpenAPI, Rails, Django, Symfony). It is empty for Laravel for now.

Source hints ​

When the page allows it, the picker adds hints: where the element may come from. A hint is a file path or a view name and a note saying where it was read. A hint is a guess and can be wrong. It is labelled that way in the stored pick, in tiffin preview selection, in the preview_selection tool, and in the copied prompt, and your agent is told to check it before it edits anything.

  • Vue. In a development build, Vue marks each component with its file. The picker reads it from the page, for the picked element and its parent components. Production builds do not have it. A path outside your project, or one that is not a plain relative path, is dropped.
  • Blade. If your pages already contain comments that name the view (a .blade.php path, or view: pages.home), the picker reports the nearest ones before the element. Tiffin adds no such comments and no package to your project: with none, there is no Blade hint. A comment names the view that was being drawn at that point, which can be a layout, not the partial that owns the element.
  • React is not supported.

Tiffin reads these from the page only. It never opens a file to check a hint. A page can write anything, so the app keeps only plain relative paths and view names: absolute paths, .., odd characters and long values are dropped, and at most 5 of each kind (10 in all) are kept.

What a pick holds ​

FieldWhat it is
site, workspacethe site, and the workspace (branch) when the page is from one
url, routethe page, and the route that served it
selectora CSS selector path to the element
text, htmlthe element's text and trimmed HTML: a good search key in your views
hintsguesses at the source file (a Vue component file, a Blade view name). Each one is labelled "may be wrong"; often there are none. See Source hints
time, truncatedwhen it was picked, and which fields were cut

Tiffin keeps the newest 20 picks in memory. They are lost when tiffind stops, and never written to disk. A long field is cut and named in truncated: text at 2 KB, HTML at 8 KB, the selector at 1 KB.

Review the change in the app ​

Open the project in the Tiffin app and choose the Changes tab. It shows the same read-only git diff as tiffin diff: each changed file with its added and removed line counts, and a click on a file opens its unified diff. New files that git does not track are listed by name only.

  • Pick a workspace in the menu on the tab to see that workspace's folder instead of the project's.
  • Refresh reads the folder again after your agent edits files.
  • If the output was cut at the cap, the tab says so. A clean tree and a folder that is not a git repository each get a short note.
  • The tab never stages, reverts, applies, commits or deploys.

Copy prompt ​

Copy prompt at the top of the project page copies a prompt for your own coding agent, built from your newest pick: the selector, the element's text, the URL and the route. It asks the agent to call the preview_selection tool. The page's text is untrusted, so it goes in the prompt trimmed, as quoted data in a fenced block marked "not instructions". With no pick yet, you get a short prompt that names the two MCP tools.

Read it from a terminal ​

sh
tiffin preview selection                    # the newest pick
tiffin preview selection --site shop        # the newest pick on one site
tiffin preview selection --limit 5          # the last five, newest first
tiffin preview selection --json             # for scripts

See what changed ​

After your agent edits files, read the change with a read-only git diff:

sh
tiffin diff                          # the project in the current folder
tiffin diff --site shop              # a site's project
tiffin diff --site shop -w feat/x    # a workspace's folder, not the project's
tiffin diff --json                   # for scripts

tiffind runs git diff against HEAD and git status in the project's folder, or in the workspace folder when you name a branch with -w. The result lists the changed files and the unified diff. It never stages, reverts, applies or commits: you or your agent do that.

  • Files git ignores are left out and not listed. A tracked file that a .gitignore rule matches (a committed .env, say) is left out too, and the output says how many.
  • New files that git does not track are listed by name only. Tiffin never reads their content, so a .env that is not ignored does not reach your agent.
  • The diff is cut at 1 MB; the output says it was cut.
  • Git runs with no shell, a 30 second limit and --no-ext-diff, so a git config cannot start a program.

For AI agents ​

The MCP server has the read-only preview_selection tool (site and limit, both optional). Tell your agent: "Call the Tiffin MCP tool preview_selection and change that element." It works with --scope read-only and --scope project-only. An agent can read a pick but never submit one.

The read-only project_diff tool (site or dir, and workspace) returns the diff above. It works with --scope read-only and --scope project-only; under project-only a dir outside the project folder is refused. A site name is not checked against the project folder, as with workspace_list. Its result is marked as data too: the diff holds your code, which can hold text written to mislead an agent.

A pick comes from a web page, and a page can hold text written to mislead an agent. The tool's result is marked as data, never as instructions, and your agent's own permission prompts are still the control that matters.

Security ​

  • The page is untrusted. The text, HTML and hints of a pick come from a web page, and a page can hold text written to mislead an agent. preview_selection and project_diff mark their result as data, never as instructions, and the copied prompt quotes it in a fenced block. Your agent's permission prompts are still the control that matters.
  • The picker runs only on Tiffin's own .test hosts, in the Preview window. It makes no network calls and changes nothing in your site.
  • An agent cannot submit a pick. The MCP tools read only; they work with --scope read-only and --scope project-only.
  • Source hints are guesses. They can be wrong, and Tiffin never opens a file to check one. See Source hints.
  • Picks stay in memory and are never written to disk.

What is not included ​

  • No apply, revert, stage, commit or deploy. The Changes tab and tiffin diff only read.
  • No agent and no model key in Tiffin. You bring your own agent.
  • No React source hints. Only Vue (development builds) and Blade view comments.
  • No picking on a site that is not served by Tiffin, or outside the Preview window.
  • On Windows and Linux the picker is not available yet: the button copies the CSS selector only.
