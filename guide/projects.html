Projects: tiffin up ​

Describe what a project needs in a tiffin.toml at its root, commit it with the code, and anyone on the team brings it up with one command:

toml
[runtimes]
php = "8.4"
node = "22"

[services]
postgres = { version = "18", databases = ["shop", "shop_test"] }
valkey = "9"

[site]
name = "shop"
https = true

[processes]
queue = "php artisan queue:work"
vite = "npm run dev"
bash
tiffin up

tiffin up, in the project folder or any folder below it:

  1. installs the runtimes and services that are missing;
  2. starts the services;
  3. creates the databases;
  4. serves the site (and redirects to HTTPS, with https = true);
  5. starts the processes.

Running it again changes nothing, and needs no network once everything is installed. In the app, Add → Run tiffin.toml… on the Projects screen does the same.

Every key is described in the tiffin.toml reference. A new Laravel or WordPress project gets one from tiffin new.

Processes ​

[processes] names the commands a project keeps running: queue workers, the scheduler, dev servers. tiffind runs them in the project folder with the project's own php and node, starts a crashed one again, and stops them all when it stops.

bash
tiffin proc                  # what runs, with its state
tiffin proc start            # this project's, from its tiffin.toml (or: start queue)
tiffin proc logs queue -f    # its output
tiffin proc restart queue    # after changing code a worker has loaded
tiffin proc stop queue

The app's Services screen shows them under Project processes, with their state, restarts and logs.

A process is named <project>/<name> (shop/queue), or just by its name when only one project has it. Commands run without a shell, so &&, | and > don't work: put the steps in a script and run that. A process that crashes at once five times in a row is marked failed; tiffin proc logs says why.

On Linux and macOS a stopping process gets SIGTERM and five seconds to finish (a queue worker finishes its job). On Windows it is ended at once, with everything it started.

Checking a project ​

tiffin check compares what a project asks for with what Tiffin has for its folder, and says how to fix each difference. It changes nothing.

bash
tiffin check            # the project in this folder
tiffin check ~/Sites/shop
ChecksAgainst
composer.json's phpthe PHP this folder runs (tiffin use, tiffin.toml or the default)
composer.json's ext-*that PHP's extensions, and whether each is on
.env.env.example's variables, and an empty APP_KEY
.env's service settingswhat Tiffin runs (tiffin env)
package.json's engines.nodethe Node this folder runs
text
Checking shop.test (/home/ada/Sites/shop)
FAIL  composer.json asks for PHP >=8.1 <8.4; this folder runs 8.4.23
      fix: tiffin use shop 8.3
FAIL  composer.json needs ext-redis; PHP 8.4.23 doesn't have it
      fix: tiffin php ext add <its .so or .dll> --version 8.4
warn  DB_PORT is "3306" in .env; Tiffin's is "5432" (Database)
      fix: tiffin env (the lines to paste)
ok    Node 22.11.0 meets package.json's >=20

It exits 1 when a check fails, so it fits a script. In the app, Check project… in a site's ⋯ menu on Projects shows the same, with each fix to copy.
