Services and databases ​

Databases, caches, message brokers and search engines run as services: PostgreSQL, MariaDB, MySQL, Valkey (a Redis-compatible server; in tiffin.toml, redis means Valkey too), MongoDB, Memcached (Linux and macOS), NATS, RabbitMQ, Mailpit, Meilisearch, Typesense, Qdrant and Silo (the maintained fork of MinIO for S3 storage; minio means Silo). Each runs on 127.0.0.1 only, on its own port, under your account.

Run one ​

bash
tiffin add postgres 18
tiffin service start postgres        # waits until it answers
tiffin service list                  # instances, ports, state
tiffin service logs postgres@18 -f
tiffin service stop postgres@18

An instance is one data folder, named after its major version (postgres@18), so two projects that use PostgreSQL 18 share one server. Give an instance its own port with --port; it's remembered. tiffind restarts the instances that were running when it last stopped.

MongoDB

tiffin add mongodb gives you MongoDB Community Server (the newest 9.0, 8.0 and 7.0) with mongod and the mongosh shell. Each major version keeps its own data. On Linux it's MongoDB's Ubuntu 22.04 build, which needs glibc 2.35 or newer and the system's OpenSSL 3 (any current distribution); Windows on Arm runs the x64 build. Tiffin's PHP has the mongodb extension, off until tiffin php ext enable mongodb.

Ports and settings ​

bash
tiffin service port postgres@18 5433                # a running one restarts on it
tiffin service set postgres@18 shared_buffers 256MB # restarts it to read the setting
tiffin service set mysql max_connections 300
tiffin service settings postgres@18                 # yours, and where its files are
tiffin service unset postgres@18 shared_buffers

Settings are written into the instance's conf.d folder (as 10-tiffin.conf, or 10-tiffin.cnf for MySQL and MariaDB), which PostgreSQL, MySQL, MariaDB and Valkey read after the configuration Tiffin generates. A few settings are Tiffin's own (the port, the data folder, listening on 127.0.0.1 only) and can't be set this way. Values are plain: letters, digits, spaces and _ . , : / @ + % * -. For anything else, put a file of your own in the same conf.d folder; it is never changed. A setting the server rejects keeps it from starting: tiffin service logs says why, and tiffin service unset undoes it.

In the app, a service card's Port and settings button does the same, and opens its configuration folder.

NATS & Qdrant

  • tiffin add nats installs the official NATS Server (nats-server) with JetStream storage enabled.
  • tiffin add qdrant installs Qdrant Vector Search Engine (qdrant) with its built-in web dashboard accessible at http://127.0.0.1:6333/dashboard.

Mailpit

tiffin add mailpit provides Mailpit (mailpit) as a service, offering an alternate SMTP testing server with its own fast web UI at http://127.0.0.1:8025 alongside Tiffin's built-in Mail screen.

RabbitMQ

RabbitMQ runs on Erlang: tiffin add rabbitmq adds Erlang 28 too when no Erlang 28 or 27 is installed. Its node is rabbit-<port>@localhost, so on the command line rabbitmqctl -n rabbit-5672@localhost status (Linux and macOS; on Windows RabbitMQ's own .bat tools aren't put on PATH). Run one RabbitMQ version at a time: the management UI's port is fixed.

Databases ​

bash
tiffin db create shop
tiffin db list
tiffin db backup shop                # to a timestamped .sql.gz in Tiffin's backups folder
tiffin db backup shop ~/shop.sql.gz
tiffin db restore shop ~/shop.sql.gz
tiffin db drop shop                  # asks first

With one database server running, tiffin db uses it; otherwise pick one with --service postgres@18. A project's tiffin.toml can create its databases for you: see Projects.

Snapshots ​

Keep a database as it is, and go back to it after a test run, a seeder, or a migration gone wrong:

bash
tiffin db snapshot save shop seeded     # a label, or none for the time
tiffin db snapshot list shop
tiffin db snapshot restore shop seeded  # or the newest, without a label (asks first)
tiffin db snapshot restore shop before-restore   # undo that restore
tiffin db snapshot delete shop seeded

A restore makes the database exactly what the snapshot holds: it's dropped and loaded again. What it held just before is kept as the snapshot before-restore first, so a restore can always be undone. If loading fails, the data is in before-restore.

Snapshots are kept in Tiffin's data folder, per server and database. In the app, a database's ⋯ menu on Databases has Snapshots….

Your app's .env ​

tiffin env prints the lines a Laravel app needs for what Tiffin runs: APP_URL, the database (what the project's tiffin.toml asks for, else what runs), Redis, Memcached, MongoDB (MONGODB_URI, for mongodb/laravel-mongodb), Scout's search engine, the S3 disk, the mail catcher and the dumps receiver.

bash
tiffin env              # in the project's folder
tiffin env shop

Paste what you need into .env; Tiffin never writes to it. The app has Copy .env settings in a site's ⋯ menu on Projects.
