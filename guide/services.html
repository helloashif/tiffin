Services and databases ​

Databases, caches, message brokers and search engines run as services: PostgreSQL, MariaDB, MySQL, Valkey (a Redis-compatible server; in tiffin.toml, redis means Valkey too), MongoDB, Memcached (Linux and macOS), NATS, RabbitMQ, Mailpit, Meilisearch, Typesense, Qdrant and Silo (the maintained fork of MinIO for S3 storage; minio means Silo). Each runs on 127.0.0.1 only, on its own port, under your account.

Run one ​

bash
tiffin add postgres 18
tiffin service start postgres        # waits until it answers
tiffin service list                  # instances, ports, state
tiffin service logs postgres@18 -f
tiffin service stop postgres@18

An instance is one data folder, named after its major version (postgres@18), so two projects that use PostgreSQL 18 share one server. Give an instance its own port with --port; it's remembered. tiffind restarts the instances that were running when it last stopped.

MongoDB

tiffin add mongodb gives you MongoDB Community Server (the newest 9.0, 8.0 and 7.0) with mongod and the mongosh shell. Each major version keeps its own data. On Linux it's MongoDB's Ubuntu 22.04 build, which needs glibc 2.35 or newer and the system's OpenSSL 3 (any current distribution); Windows on Arm runs the x64 build. Tiffin's PHP has the mongodb extension, off until tiffin php ext enable mongodb.

Ports and settings ​

bash
tiffin service port postgres@18 5433                # a running one restarts on it
tiffin service set postgres@18 shared_buffers 256MB # restarts it to read the setting
tiffin service set mysql max_connections 300
tiffin service settings postgres@18                 # yours, and where its files are
tiffin service unset postgres@18 shared_buffers

Settings are written into the instance's conf.d folder (as 10-tiffin.conf, or 10-tiffin.cnf for MySQL and MariaDB), which PostgreSQL, MySQL, MariaDB and Valkey read after the configuration Tiffin generates. A few settings are Tiffin's own (the port, the data folder, listening on 127.0.0.1 only) and can't be set this way. Values are plain: letters, digits, spaces and _ . , : / @ + % * -. For anything else, put a file of your own in the same conf.d folder; it is never changed. A setting the server rejects keeps it from starting: tiffin service logs says why, and tiffin service unset undoes it.

In the app, the Services screen groups cards by kind (Databases, Cache and queue, Search, Storage, Mail) from each package's manifest, and Overview provides start, stop and restart buttons for every service. A service card's Port and settings button changes ports and settings and opens its configuration folder.

NATS & Qdrant

  • tiffin add nats installs the official NATS Server (nats-server) with JetStream storage enabled.
  • tiffin add qdrant installs Qdrant Vector Search Engine (qdrant) with its built-in web dashboard accessible at http://127.0.0.1:6333/dashboard.

Mailpit

tiffin add mailpit provides Mailpit (mailpit) as a service, offering an alternate SMTP testing server with its own fast web UI at http://127.0.0.1:8025 alongside Tiffin's built-in Mail screen.

RabbitMQ

RabbitMQ runs on Erlang: tiffin add rabbitmq adds Erlang 28 too when no Erlang 28 or 27 is installed. Its node is rabbit-<port>@localhost, so on the command line rabbitmqctl -n rabbit-5672@localhost status (Linux and macOS; on Windows RabbitMQ's own .bat tools aren't put on PATH). Run one RabbitMQ version at a time: the management UI's port is fixed.

Databases ​

bash
tiffin db create shop
tiffin db list
tiffin db backup shop                # to a timestamped .sql.gz in Tiffin's backups folder
tiffin db backup shop ~/shop.sql.gz
tiffin db restore shop ~/shop.sql.gz
tiffin db drop shop                  # asks first

With one database server running, tiffin db uses it; otherwise pick one with --service postgres@18. A project's tiffin.toml can create its databases for you: see Projects.

Look at the data ​

See what is in a database without another tool:

bash
tiffin db tables shop                      # tables and views (PostgreSQL: --schema audit)
tiffin db describe shop users              # columns, indexes, foreign keys
tiffin db describe shop users --ddl        # the CREATE statement
tiffin db query shop "SELECT id, email FROM users LIMIT 5"
tiffin db query --read-only shop -f report.sql --json
echo "SELECT 1" | tiffin db query shop -

query runs one statement and shows its rows, or how many rows it changed. It shows at most 100 rows (--limit, up to 10000) and says when there were more. A very wide value is cut and marked, bytes show as <binary, N bytes>, and --json gives every value as text, so no number loses digits.

--read-only makes the server refuse any change, whatever the SQL says. A statement the server refuses prints the server's own message. MySQL has no schemas beside the database, so name the database for tables; for PostgreSQL it defaults to postgres, and the schema to public.

Browse in the app ​

On Databases, a database's Browse button opens a page of its own, with the tables on the left and tabs on top. A click on a table opens it in the preview tab (in italics, replaced by the next click); a double click keeps it open, and so does any change you stage. Open as many tables as you like, and use Query (or Ctrl/Cmd+T) for a SQL tab; a tab with changes waiting shows a dot, and closing it, or leaving the page, asks first. The rows are 50 to a page: click a column to sort, type a condition such as age > 30 AND name LIKE 'a%' to filter (the server checks it, and says if it is wrong). Structure shows the columns, keys, indexes, foreign keys and the CREATE statement; a Query tab is a SQL editor.

Rows can be added, changed and deleted, and changes are staged: double-click a cell to edit it in place (Enter keeps it, Esc cancels), use the pencil to edit a whole row in the panel that opens at the right, the bin to delete a row, Add row for a new one. Changed cells are tinted, deleted rows struck through and new rows shown at the end, with a bar that says how many changes are waiting. Nothing reaches the database until you press Commit, which makes all of them in one transaction: if any change cannot be made (a row was deleted elsewhere, a unique value is taken) none is, the bar names the change that failed, and everything stays staged so you can fix it. Discard throws them away. Reading the rows again (a page, a sort, a filter) asks first when changes are waiting; Ctrl/Cmd+S commits.

An edit finds its row by the primary key, so a table without one, and a view, can be read but not edited (a row can still be added to a table without a key). A value that is bytes, or too long to show whole, is shown as <binary, 12 bytes> or cut with …, and is left as it is when you edit the rest of the row.

A cell of a foreign key has a small arrow: click it to open the row it points at; Back returns to where you were. JSON columns are edited in a text area that says whether the JSON is valid and can lay it out (Format never changes a number).

Import, export, clone, empty, drop ​

The Table menu above the rows has:

  • Export as CSV, JSON or SQL INSERT statements: the table as it is shown (its filter and sort). Tiffin writes the whole file or nothing, with no limit on rows. In CSV an empty field is NULL and an empty string is ""; bytes are written as base64 text (only SQL gives them back as bytes). A SQL result has an Export menu too, which writes all of the statement's rows.
  • Import a CSV or JSON file into the table. You see the first rows of the file and where each column will go (by name, or choose; Skip leaves one out), then every row is added in one transaction: if one cannot be, none is, and the dialog names the line. A CSV needs a header row unless you say the first line is data. To run a .sql file use Restore on the database.
  • Clone copies a table's structure, and the rows if you ask, to a new table. Empty removes every row and keeps the table; Drop removes the table or view. Both say what they do first, and PostgreSQL's CASCADE is a box you tick.

From a terminal:

bash
tiffin db export shop users users.csv                      # or users.json, users.sql
tiffin db export shop orders recent.json --where "created > '2026-01-01'" --order id:desc
tiffin db export shop --sql "SELECT id, total FROM orders" report.csv
tiffin db import shop users users.csv --preview            # the first rows and the column mapping
tiffin db import shop users people.csv --map name=full_name --map notes=
tiffin db table clone shop users users_backup --with-data
tiffin db table truncate shop users                        # asks first
tiffin db table drop shop users_backup --yes

The SQL editor ​

The editor colours your SQL and completes as you type: keywords, the database's tables, and a table's columns once you have named it (users., or Ctrl+Space). Several statements can be in it at once, separated by ;.

  • Run (⌘↵ or Ctrl+Enter) runs the selection, or else the statement the cursor is in. Run all (⇧⌘↵) runs every statement in order and stops at the first one the server refuses. Each statement gets its own result tab.
  • Explain shows how the server would run the statement, without running it. Format lays the SQL out (⌥⇧F), the selection or all of it.
  • Read-only makes the server refuse any change, whatever the SQL says.
  • History lists what you ran on this database, with what the server answered; click one to put it back in the editor. Tiffin keeps the last 500 per server, also for tiffin db query (see below). Statements are kept as typed, so clear a run, or all of them, that holds a password.
  • Saved keeps queries you name, in the snippets on the Tools screen (language sql, group Queries).

A MySQL DELIMITER line, or a BEGIN … END body with ; in it, is read as several statements: select it and use Run on the selection.

bash
tiffin db history shop            # what ran on shop, newest first
tiffin db history --clear         # forget it all (or name a database)
tiffin db query --no-history shop "CREATE USER ..."

Look at the database itself ​

The Tools menu above a workspace's tabs opens four more views of the database. Each is a tab that stays while you look at another.

  • Processes lists the other sessions on the server: who, in which database, what state, for how long, and the statement. It refreshes every three seconds while it is the tab in front. Pick a session to read its whole statement, then Cancel statement (the query stops, the session stays) or End session; both ask first. A connection in safe mode can look but not stop anything. A SQLite file has no other sessions.
  • Users lists the users or roles with what each can do (superuser, can log in, can create databases, locked…) and the roles it belongs to, and shows a user's privileges as GRANT statements. Passwords are never read. To make a user, use Users & password on Tiffin's own services, or SQL.
  • Views, functions & triggers lists what a schema holds besides tables; pick one to read the statement that creates it, copy it, or Open in a query tab to change it.
  • ER diagram & DDL draws the tables you tick, with their columns and foreign keys, as an entity-relationship diagram (zoom, and Copy Mermaid to use it elsewhere). The related tables are ticked to start with. DDL shows the CREATE statements of the same tables with the tables others point at first, so the text can be run as it is.

From a terminal, with the same text:

bash
tiffin db processes                      # or: --service conn:prod
tiffin db kill 4242 --terminate          # asks first
tiffin db users --grants app             # or app@10.0.0.% on MySQL
tiffin db objects shop --kind trigger
tiffin db objects shop --show add_one    # the statement that creates it
tiffin db diagram shop > shop.mmd
tiffin db ddl shop --tables users,orders > schema.sql

Saved connections ​

Besides Tiffin's own services, Databases can open a SQLite file or a PostgreSQL, MySQL or MariaDB server that Tiffin does not run: a staging copy, a production replica, a database in a container. Save it once and it is listed under Connections on the left, by group, with a lock when it is in safe mode.

New opens a page of its own. Pick the type, then either paste a URL (postgres://user:password@host:5432/database?sslmode=require, mysql://…, sqlite:///path/to/file.db) and press Fill in, or type the host, port, user, password and database. TLS is off, used when the server has it, required, or required with the certificate checked; asking for TLS from a server that has none fails and says so. Test connection connects with what is in the form and says the server's version and its databases, without saving anything. A tag (local, dev, test, staging, production) colours the connection so you know where you are.

Safe mode makes a connection read only. You can look at rows, run queries that read and export, but not change a row, import, clone, empty or drop anything, and a statement that is not read only is refused before it is sent. Turn it on for production.

The password goes to tiffind, which keeps it in a file only you can read inside Tiffin's data folder (connections/). It is not encrypted, it is never shown again, and it is never put in a URL or a log. Leave the field alone when you edit a connection and the saved password stays; tick Forget the saved password to remove it.

A saved connection is named conn: and its id, and the terminal takes it wherever it takes a service:

bash
tiffin db conn add --url postgres://app@db.example.test:5432/shop --tls require --tag staging --password-stdin < pw.txt
tiffin db conn add Notes --kind sqlite --path ~/notes.db --safe
tiffin db conn list
tiffin db conn test shop
tiffin db --service conn:shop tables shop
tiffin db --service conn:notes query "SELECT count(*) FROM notes"

Through an SSH host ​

A server that only a bastion can reach is a connection with an SSH tunnel: switch it on in the form and give the SSH host, port, user, and how you log in: your SSH agent, a key file (and its passphrase, if it has one), or a password. The Host and Port above are then the database as the SSH host sees it, often 127.0.0.1 or an internal name such as db.internal. Everything else (browsing, queries, safe mode) works as for any connection; the connection shows "via" and the SSH host. The SSH password or passphrase is kept like the database password: in a private file, never shown again.

Tiffin never logs in to an SSH host it has not been told to trust. The first Test connection stops and shows the host's fingerprint; check it is your server's (on the server, ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub), then press Trust this host and test again. Tiffin reads the key itself and keeps it only if it is the one with that fingerprint. Hosts in your own ~/.ssh/known_hosts are trusted already, and Tiffin never changes that file.

If a host's key changes, Tiffin refuses to connect and shows both fingerprints. That can mean the server was rebuilt, or that someone is between you and it. Only if you know it was changed on purpose, use Forget the old key…, then trust the new one. On Windows, use a key file or a password: the OpenSSH agent is not supported yet. Jump hosts (ProxyJump) and ~/.ssh/config are not read.

bash
tiffin db conn add Prod --url postgres://app@db.internal:5432/shop \
  --ssh-host bastion.example.test --ssh-user deploy --ssh-key ~/.ssh/id_ed25519
tiffin db conn test prod      # unknown host: prints the fingerprint and the command to trust it
tiffin db conn trust-host prod --fingerprint SHA256:…
tiffin db conn edit prod --ssh-secret-stdin < passphrase.txt   # or --no-ssh to go direct

Valkey and Redis keys ​

Valkey, and any Redis you save a connection to, hold keys, not tables. They are in the Databases list too: pick Valkey (or a saved Redis connection) and press Browse keys.

The page lists the keys of a database: type a part of a name to find keys (or a pattern such as user:*), choose a type, press Load more for the next page, and pick a key to see its value. The list is read with SCAN, never KEYS, so a big database does not freeze the server. Above the list, the database is chosen with the number of keys each holds.

A key's editor changes it at once (there is nothing to stage): a string is edited in place and saving keeps its time to live; a hash, list, set or sorted set shows a page of its elements, to edit, add or remove one at a time; a stream is read only. You can set when a key expires (in seconds) or make it never expire, rename it (never over another key), or delete it. Values that are not text are shown as bytes and not edited. New makes a key, and says if the name is taken. Flush empties the database, and asks first, naming it.

The Console tab is like redis-cli: type HGETALL user:1 or SET k "a b", with the arrow keys for the last commands. Commands that wait or stream (MONITOR, SUBSCRIBE, BLPOP…) are not run here. The Info tab shows the server's version, memory and settings, and how many keys each database has.

To save a Redis server, choose Redis / Valkey in New connection: host, port, an ACL user if it has one, a password, the database index and TLS (rediss:// in a URL is TLS with the certificate checked). An SSH tunnel and safe mode work as for any connection: in safe mode keys can be read, not changed, and the console runs only commands the server itself calls read only.

bash
tiffin db conn add --url redis://:password@cache.example.test:6379/0 --tag staging
tiffin kv keys 'user:*' --type hash --service conn:cache-example-test
tiffin kv get user:1
tiffin kv set greeting hello --ttl 1h
tiffin kv ttl greeting --persist
tiffin kv cmd INFO memory
tiffin kv flush --db 3                 # asks first

MongoDB ​

MongoDB holds collections of documents, not tables, so it has its own page too. Pick MongoDB (or a saved MongoDB connection) in the Databases list and press Browse collections.

On the left are the databases with their size, and under each its collections with how many documents they hold (a view says view). Search to narrow the list; New collection and the drop buttons are on a database's row and a collection's row; a drop asks first.

A collection has four tabs:

  • Documents reads a page of 20, 50 or 100. The Filter, Sort and Projection boxes take Extended JSON, such as { "status": "open" }; they say where the JSON goes wrong before anything is sent. Show the page as a list or a table, and page with the arrows; the count of matches is beside them. Pick a document to edit it as canonical Extended JSON, which keeps every type (a 64-bit number stays 64-bit, a date stays a date). Save replaces the document with the same _id; Insert, Duplicate and Delete do what they say, and delete asks first. A document over 1 MiB is listed by its _id and is not edited here.
  • Indexes shows the collection's size and its indexes, makes one from keys such as { "email": 1 } (unique, sparse, expire after some seconds) and drops one. _id_ is kept.
  • Aggregate runs a pipeline, a list of stages, and shows up to 100 documents.
  • Info shows the server's version, uptime, connections and memory.

To save a server, choose MongoDB in New connection: host, port, user, password, a default database, and the authentication database (where the user is defined, usually admin). mongodb://user:password@host:27017/app?authSource=admin fills the form; tls=true means the certificate is checked. Tiffin connects to one server: a list of hosts and mongodb+srv:// are refused, so a replica set is reached through one member. An SSH tunnel works as for any connection.

In safe mode documents can be read, not changed, and a pipeline with $out or $merge (anywhere in it) is refused, as is anything that runs JavaScript on the server ($where, $function, $accumulator).

bash
tiffin db conn add --url mongodb://app:password@db.example.test:27017/shop?authSource=admin --tag staging
tiffin mongo dbs
tiffin mongo collections shop --service conn:db-example-test-shop
tiffin mongo find shop orders --filter '{"status": "open"}' --sort '{"_id": -1}' --limit 10
tiffin mongo get shop orders 507f1f77bcf86cd799439011
echo '{"name": "new"}' | tiffin mongo insert shop orders
tiffin mongo rm shop orders 507f1f77bcf86cd799439011     # asks first
tiffin mongo drop shop orders                            # asks first

Snapshots ​

Keep a database as it is, and go back to it after a test run, a seeder, or a migration gone wrong:

bash
tiffin db snapshot save shop seeded     # a label, or none for the time
tiffin db snapshot list shop
tiffin db snapshot restore shop seeded  # or the newest, without a label (asks first)
tiffin db snapshot restore shop before-restore   # undo that restore
tiffin db snapshot delete shop seeded

A restore makes the database exactly what the snapshot holds: it's dropped and loaded again. What it held just before is kept as the snapshot before-restore first, so a restore can always be undone. If loading fails, the data is in before-restore.

Snapshots are kept in Tiffin's data folder, per server and database. In the app, a database's ⋯ menu on Databases has Snapshots….

Your app's .env ​

tiffin env prints the lines a Laravel app needs for what Tiffin runs: APP_URL, the database (what the project's tiffin.toml asks for, else what runs), Redis, Memcached, MongoDB (MONGODB_URI, for mongodb/laravel-mongodb), Scout's search engine, the S3 disk, the mail catcher and the dumps receiver.

bash
tiffin env              # in the project's folder
tiffin env shop

Paste what you need into .env; Tiffin never writes to it. The app has Copy .env settings in a site's ⋯ menu on Projects.
