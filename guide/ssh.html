SSH keys and identities ​

In the app this is the SSH screen: make or import a key, save an identity for it, test it against GitHub or your server, copy its public key. New project → Clone uses the same identities.

Tiffin keeps SSH identities: a private key, the hosts it is for (such as github.com or *.example.com) and an optional user name. It uses them when it runs git over SSH, so a work account and a personal account can live side by side without editing ~/.ssh/config.

bash
tiffin ssh key list                    # the keys in ~/.ssh
tiffin ssh key new id_work --label Work --host github.com --user git
tiffin ssh key show ~/.ssh/id_work     # the public key to paste into GitHub
tiffin ssh test work github.com        # does GitHub accept it?
tiffin ssh id list
tiffin ssh agent                       # is the SSH agent running, and which keys it holds

Which identity is used ​

For a host, in this order: the identity chosen for the project folder (tiffin ssh id use <id> <folder>), the best match among the identities' hosts (an exact name beats *.example.com), the default (tiffin ssh id default <id>), then ssh's own keys. tiffin ssh id which <host> shows the result.

Keys and passphrases ​

tiffin ssh key new makes an ed25519 key in ~/.ssh; key import copies one in. A passphrase can be saved with the identity (tiffin ssh id add <label> --key <path> --passphrase): it is kept in a private file, never in the database or in a log, and Tiffin's own program answers ssh's prompt from it. Without a saved passphrase, a key must be in your SSH agent; on Windows that is the OpenSSH Authentication Agent service.

tiffin ssh id rm forgets an identity. It deletes key files only with --remove-key, and only for a key Tiffin made: your own key files are never removed.

ssh and git in your own terminal ​

By default only Tiffin's own git (cloning from the app) uses these identities. Turn on tiffin ssh config on (or ssh in your terminal → Turn on… in the app) to make your own ssh and git use them too. Tiffin shows what it will write and asks first:

  • ~/.ssh/tiffin.config, a Host block per identity with hosts (an exact host before a wildcard, each with IdentitiesOnly yes, so no other key is offered to that host), and, for the default identity, a Host * block that only adds its key. Other servers keep getting the keys they had before.
  • one Include tiffin.config line, with a comment, at the top of ~/.ssh/config. Nothing else in your config is read or changed.

While it is on, saving, changing or forgetting an identity updates tiffin.config. tiffin ssh config off removes the line and the file and leaves the rest of your config byte for byte. If ~/.ssh/config is a link (a dotfile manager's), Tiffin does not touch it: add the Include tiffin.config line yourself.

Host keys ​

tiffin ssh trust-host <host> --fingerprint SHA256:… keeps a host's key if it has that fingerprint; forget-host removes it. See new projects for cloning.
