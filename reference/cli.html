Command line ​

Tiffin: runtimes, services and .test sites, per project.

Every command takes these flags:

Flag
--jsonprint machine-readable JSON
-h, --helphelp for any command
-v, --versionprint the version (tiffin alone)

tiffin add ​

Install a runtime, service or tool (version: exact, a prefix like 22, or latest).

tiffin add <name> [version]

tiffin alias ​

Give a site another name: <alias>.test serves it too (default: the site of this folder).

tiffin alias [site] <alias>

Gives a site another .test name, with the names under it (api.<alias>.test). With one argument, the site of the current folder. The alias stays with the project folder; tiffin unalias removes it.

tiffin autostart ​

Start tiffind at login (status, enable, disable).

tiffin autostart

Start tiffind when you log in, so sites and services are ready without running a command first. The desktop app has its own switch, which starts the app in the tray (and tiffind with it). No password needed.

tiffin autostart disable ​

Do not start tiffind (or with --app, the desktop app) at login.

tiffin autostart disable [flags]
Flag
--appthe desktop app (tiffin-gui) next to this tiffin, in the tray

tiffin autostart enable ​

Start tiffind (or with --app, the desktop app) at login.

tiffin autostart enable [flags]
Flag
--appthe desktop app (tiffin-gui) next to this tiffin, in the tray

tiffin autostart status ​

Show what starts at login.

tiffin autostart status

tiffin bom ​

Find (and with --clean remove) UTF-8 byte order marks.

tiffin bom <folder> [flags]

Lists the files in a folder that start with a UTF-8 BOM (EF BB BF), which PHP prints before anything else. --clean rewrites them without it. Folders named by --exclude are skipped (default: .git .svn .idea .vscode node_modules vendor); links are never followed.

Flag
--cleanremove the BOMs
--exclude stringSlicefolder names to skip
--ext stringSliceonly files with these extensions (php,js); default: every file

tiffin cert make ​

Make a certificate for host names and IP addresses.

tiffin cert make <name>... [flags]

Signs a certificate for the names (wildcards such as *.shop.test, and IP addresses) with Tiffin's CA, which signs only .test names, localhost and loopback addresses, or with --ca new by a CA made for it: that CA is limited to these names and its key is thrown away. Nothing is added to a trust store. Prints the certificate and key, or writes them to --out.

Flag
--ca stringwho signs it: tiffin, or new (a CA made for it) (default tiffin)
--days inthow long it is valid (at most 825) (default 397)
--ecdsaan ECDSA P-256 key instead of RSA-2048
--out stringwrite the files to this folder instead of printing them

tiffin check ​

Check a project against what Tiffin has: PHP, extensions, .env, Node.

tiffin check [folder] [flags]

Compares what the project in a folder (default: this one) asks for with what Tiffin has for it, and says how to fix each difference (ADR 0102):

- composer.json's PHP version and ext-* extensions, with the PHP this
  folder runs;
- .env against .env.example, and an empty APP_KEY;
- the services' settings in .env against what Tiffin runs (tiffin env);
- package.json's engines.node with the Node this folder runs.

It changes nothing, unless --fix is given. It exits 1 when a check fails.

--fix does what it can by itself (ADR 0132), then checks again: it installs PHP or Node, switches the site's PHP (tiffin use), turns PHP extensions on, makes .env and APP_KEY, and adds .env.example's missing variables to .env. A .env's service settings and tiffin.toml pins stay for you. --only limits it to some areas: php, extensions, env, node.

bash
  tiffin check
  tiffin check --fix
  tiffin check ~/Sites/shop --fix --only env
Flag
--fixfix what Tiffin can by itself, then check again
--only stringSlicewith --fix: only these areas (php, extensions, env, node)

tiffin config ​

Show or change where tiffind listens: dns, mail, dumps.

tiffin config

The addresses of the .test resolver (dns), the mail catcher (mail) and the dumps receiver (dumps), as loopback ip:port. A change applies when tiffind restarts (--restart does it now); an environment variable such as TIFFIN_SMTP_ADDR wins over a saved address. A new dns address also needs tiffin elevate again.

bash
  tiffin config
  tiffin config set mail 127.0.0.1:2526 --restart
  tiffin config unset mail

tiffin db conn

--path stringthe database file (sqlite)
--port intthe server's port (default: the engine's)
--safesafe mode: the connection can be read, not changed
--ssh-auth stringpassword, key or agent (default: key with --ssh-key, password with --ssh-secret-stdin, else agent)

--ssh-user stringthe SSH user
--tag stringlocal, dev, test, staging or production (a colour in the app)
--tls stringdisable, prefer, require or verify-full
--url stringa connection URL: postgres://user:password@host:5432/db, mysql://…, sqlite:///path/to/file.db
--user stringthe user

tiffin db conn trust-host ​

Trust the SSH host key of a connection, if it is the one with this fingerprint.

tiffin db conn trust-host <id> --fingerprint SHA256:… [flags]

A connection through an SSH host does not connect until Tiffin knows the host's key. A failed test or command shows the fingerprint; check it is your server's (ask whoever runs it, or run ssh-keygen -lf on its public key), then give it here. Tiffin reads the key itself and keeps it only if it has this fingerprint. A host whose key is known and different is refused: forget-host first, if the server was rebuilt.

Flag
--fingerprint stringthe host key's fingerprint, SHA256:… as shown

tiffin db export ​

Write a table, or the rows of a query, to a CSV, JSON or SQL file.

tiffin db export [database] <table> <file> [flags]

Write a table to a file as CSV, JSON or SQL INSERT statements, the format taken from the file's extension unless --format says. --where and --order pick rows; --sql writes the rows of one statement instead of a table (tiffin db export [database] --sql "SELECT ..." <file>). The file is written whole or not at all, with no limit on rows, and an existing one is replaced only with --force.

In CSV an empty field is NULL and an empty string is "", so tiffin db import can tell them apart.

bash
  tiffin db export shop users users.csv
  tiffin db export shop orders recent.json --where "created > '2026-01-01'" --order id:desc
  tiffin db export shop --sql "SELECT id, total FROM orders" report.csv
Flag
--delimiter stringCSV: the field separator, one character, or tab (default comma)
--forcereplace the file if it exists
--format stringcsv, json or sql (default: by the file's extension)
--into stringSQL of a --sql statement: the table name the INSERTs use
--no-headerCSV: leave the column names out
--order stringSliceorder by a column, col or col:desc (repeat or comma-separate)
--schema stringthe PostgreSQL schema (default public)
--sql stringwrite the rows of this statement instead of a table
--where stringonly the rows that match this condition, as after WHERE

Flag

tiffin db import ​

Add the rows of a CSV or JSON file to a table.

tiffin db import [database] <table> <file> [flags]

Add the rows of a CSV or JSON file to an existing table, in one transaction: every row or none. The format is taken from the extension unless --format says. A CSV needs a header row unless --no-header (then its columns are named 1, 2, ...); a JSON file is an array of objects. File columns go to the table columns of the same name, ignoring case; --map file=column chooses others (--map file= skips one). In CSV an empty field is NULL and an empty string is ""; --null-token adds a word that means NULL.

--preview shows the file's first rows and where its columns would go, and adds nothing. A SQL file is loaded with tiffin db restore.

bash
  tiffin db import shop users users.csv
  tiffin db import shop users people.csv --map name=full_name --map notes=
  tiffin db import shop users users.csv --preview
Flag
--delimiter stringCSV: the field separator, one character, or tab (default comma)
--format stringcsv or json (default: by the file's extension)
--map stringArrayput a file column in a table column: file=column (file= skips it)
--no-headerCSV: the first line is data, not column names
--null-token stringCSV: a field that means NULL, besides an empty one
--previewshow the first rows and the column mapping; add nothing
--schema stringthe PostgreSQL schema (default public)

tiffin dns ​

Look a name up in DNS (an IP address: its PTR name).

tiffin elevate ​

Set the system up for Tiffin once (asks for your password).

tiffin elevate [flags]

Trust Tiffin's CA (for HTTPS on .test only), send .test names to tiffind and, on Linux, let tiffind use ports 53, 80 and 443. On Linux it also, when needed, stops another local tool's system services that hold the ports, repairs /etc/systemd/resolved.conf.d if it is not root's, and installs certutil for Chrome; it lists each step first. It asks for your password (sudo) or for permission (Windows) once; nothing else in Tiffin needs it afterwards.

Flag
-y, --yesdo not ask before changing the system (the password or UAC prompt still appears)

Runs code with PHP, Node.js, Python, Ruby, Go, Bun or Deno, as the app's code playground does: tiffind starts the runtime's own program, with a time limit, and its output streams here. The code comes from a file, from -e, or from standard input (a file of -, or a pipe).

--dir stringthe folder to run in (default: the current folder)
-l, --lang stringthe language, optionally with a version: php, node, python, ruby, go, bun, deno; php@8.3

tiffin telemetry ​

Show or switch Tiffin's anonymous usage counts.

tiffin telemetry

Tiffin counts installs and daily use, anonymously, to know what to build next. tiffind sends one "install" event, then one "daily_active" event a day, with the version, OS, architecture, how Tiffin was installed and how many runtimes, services and sites exist. Never names, paths, domains, addresses or environment values. Nothing is sent in the first hour, or in a development build. Turn it off with tiffin telemetry off, TIFFIN_TELEMETRY=0 or DO_NOT_TRACK=1.

bash
  tiffin telemetry
  tiffin telemetry off
  tiffin telemetry on --json

tiffin tunnel ​

Serve sites on your own domain through a named Cloudflare tunnel.

tiffin tunnel

A named tunnel serves sites at hostnames on a domain of yours on Cloudflare, such as https://shop.example.com, the same address every time. It needs a Cloudflare account (free) with the domain on it:

tiffin tunnel login                        log in, in a browser, and pick the domain
tiffin tunnel create                       create the tunnel on the account
tiffin tunnel route shop shop.example.com  serve shop.test at shop.example.com
tiffin tunnel up                           start serving (until down, or tiffind stops)

For a quick address with no account, use tiffin share.

tiffin tunnel route ​

Serve a site at a hostname on your domain, through the tunnel.

tiffin tunnel route [site] <hostname> [flags]

Adds a DNS record on your Cloudflare account sending the hostname to the tunnel, and serves the site there (at once, if the tunnel is up). Without a site, the one whose folder holds the current one. A site has one hostname: routing it again replaces the old one. An existing DNS record for the hostname is left alone unless --overwrite.

tiffin use ​

Make an installed version the global default, or choose a site's PHP.

tiffin use <name> <version>

Make an installed version the global default (exact or a prefix like 20), or choose the PHP version of one site, for its pages and the php and composer commands in its folder.

tiffin use node 22          node 22 everywhere nothing else is chosen
tiffin use shop 8.3         shop.test runs PHP 8.3
tiffin use shop.test 8.3    the same; .test always means a site
tiffin use shop default     back to tiffin.toml or the global default

A name that is a package (installed or in the registry) means the package; "default" is never taken as a version.
