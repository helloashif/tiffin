Command line ​

Tiffin: runtimes, services and .test sites, per project.

Every command takes these flags:

Flag
--jsonprint machine-readable JSON
-h, --helphelp for any command
-v, --versionprint the version (tiffin alone)

tiffin add ​

Install a runtime, service or tool (version: exact, a prefix like 22, or latest).

tiffin add <name> [version]

tiffin alias ​

Give a site another name: <alias>.test serves it too (default: the site of this folder).

tiffin alias [site] <alias>

Gives a site another .test name, with the names under it (api.<alias>.test). With one argument, the site of the current folder. The alias stays with the project folder; tiffin unalias removes it.

tiffin autostart ​

Start tiffind at login (status, enable, disable).

tiffin autostart

Start tiffind when you log in, so sites and services are ready without running a command first. The desktop app has its own switch, which starts the app in the tray (and tiffind with it). No password needed.

tiffin autostart disable ​

Do not start tiffind (or with --app, the desktop app) at login.

tiffin autostart disable [flags]
Flag
--appthe desktop app (tiffin-gui) next to this tiffin, in the tray

tiffin autostart enable ​

Start tiffind (or with --app, the desktop app) at login.

tiffin autostart enable [flags]
Flag
--appthe desktop app (tiffin-gui) next to this tiffin, in the tray

tiffin autostart status ​

Show what starts at login.

tiffin autostart status

tiffin bom ​

Find (and with --clean remove) UTF-8 byte order marks.

tiffin bom <folder> [flags]

Lists the files in a folder that start with a UTF-8 BOM (EF BB BF), which PHP prints before anything else. --clean rewrites them without it. Folders named by --exclude are skipped (default: .git .svn .idea .vscode node_modules vendor); links are never followed.

Flag
--cleanremove the BOMs
--exclude stringSlicefolder names to skip
--ext stringSliceonly files with these extensions (php,js); default: every file

tiffin cert ​

Make TLS certificates.

tiffin cert

tiffin cert make ​

Make a certificate for host names and IP addresses.

tiffin cert make <name>... [flags]

Signs a certificate for the names (wildcards such as *.shop.test, and IP addresses) with Tiffin's CA, which signs only .test names, localhost and loopback addresses, or with --ca new by a CA made for it: that CA is limited to these names and its key is thrown away. Nothing is added to a trust store. Prints the certificate and key, or writes them to --out.

Flag
--ca stringwho signs it: tiffin, or new (a CA made for it) (default tiffin)
--days inthow long it is valid (at most 825) (default 397)
--ecdsaan ECDSA P-256 key instead of RSA-2048
--out stringwrite the files to this folder instead of printing them

tiffin check ​

Check a project against what Tiffin has: PHP, extensions, .env, Node.

tiffin check [folder]

Compares what the project in a folder (default: this one) asks for with what Tiffin has for it, and says how to fix each difference (ADR 0102):

- composer.json's PHP version and ext-* extensions, with the PHP this
  folder runs;
- .env against .env.example, and an empty APP_KEY;
- the services' settings in .env against what Tiffin runs (tiffin env);
- package.json's engines.node with the Node this folder runs.

It changes nothing. It exits 1 when a check fails.

tiffin config ​

Show or change where tiffind listens: dns, mail, dumps.

tiffin config

The addresses of the .test resolver (dns), the mail catcher (mail) and the dumps receiver (dumps), as loopback ip:port. A change applies when tiffind restarts (--restart does it now); an environment variable such as TIFFIN_SMTP_ADDR wins over a saved address. A new dns address also needs tiffin elevate again.

bash
  tiffin config
  tiffin config set mail 127.0.0.1:2526 --restart
  tiffin config unset mail

tiffin config set ​

Save where one of tiffind's services listens.

tiffin config set <dns|mail|dumps> <ip:port> [flags]
Flag
--restartrestart tiffind now to use it

tiffin config unset ​

Go back to the default address.

tiffin config unset <dns|mail|dumps> [flags]
Flag
--restartrestart tiffind now to use it

tiffin db snapshot

tiffin diagnostics ​

Save a zip of what helps someone else see what is wrong (for a bug report).

tiffin diagnostics [flags]

Save versions, tiffind's status, Doctor's checks, packages, sites, services, ports and Tiffin's own logs in one zip. Your home folder is written as ~, and passwords, tokens, keys and URL credentials are redacted; your apps' own logs and .env files are not included. Read it before you share it.

bash
  tiffin diagnostics
  tiffin diagnostics --out ~/Desktop/tiffin-bug.zip
Flag
--forcereplace a file already there
-o, --out stringwhere to save it (default: tiffin-diagnostics-<time>.zip here)

tiffin dns ​

Look a name up in DNS (an IP address: its PTR name).

tiffin dns <name|ip> [flags]

Asks the system's resolver, Tiffin's own DNS server (--server tiffin: how Tiffin answers a .test name) or a server you name, and shows each record with its TTL. --type ALL asks for A, AAAA, CNAME, MX, NS, TXT, SOA and CAA. The system resolver gives no TTLs and cannot look up SOA or CAA records.

bash
  tiffin dns shop.test --server tiffin
  tiffin dns example.com --type MX --server 1.1.1.1
  tiffin dns 8.8.8.8
Flag
-s, --server stringsystem, tiffin, or a server's IP address (1.1.1.1, 8.8.8.8, 9.9.9.9, ip:port) (default system)
--timeout durationgive up after this long (at most 30s) (default 5s)
-t, --type stringA, AAAA, CNAME, MX, TXT, NS, SRV, CAA, PTR, SOA or ALL (default A and AAAA)

tiffin doctor ​

Check that Tiffin works on this machine, and say how to fix what does not.

tiffin doctor [flags]

Check Tiffin end to end: the CA and its trust, .test names, ports 80 and 443, PHP. It exits 1 when something failed. With --fix it makes the fixes it can (one password or UAC prompt for those that need it, through tiffin elevate).

Flag
--bundlesave a diagnostics zip for a bug report instead (tiffin diagnostics)
--fixmake the fixes Tiffin can make
-y, --yeswith --fix: do not ask first (the password or UAC prompt still appears)

tiffin dumps ​

Your sites' PHP requests, with dumps, queries and N+1 warnings from Laravel apps.

tiffin dumps [flags]

Every PHP request Tiffin serves, any site's, to send again or copy as curl (ADR 0101). From Laravel apps with the tiffin/laravel package (composer require --dev tiffin/laravel), also their dump() values and database queries, with N+1, duplicate and slow query warnings. The newest 50 requests are kept, in memory.

Flag
-f, --followprint each request as it finishes (Ctrl+C stops)
--site stringonly this site's requests (shop or shop.test)

tiffin dumps capture ​

What Tiffin keeps of a request: dumps, queries, every site's requests.

tiffin dumps capture [<signal> on|off]

Lists what Tiffin keeps of a request, each on or off, or turns one on or off: dumps (dump() and dd() values), queries (and so their warnings) and requests (every site's PHP requests as they arrived, with headers, cookies and body, to send again). A change applies to what arrives next and is saved; what is already kept stays until tiffin dumps clear.

bash
  tiffin dumps capture
  tiffin dumps capture requests off

tiffin dumps clear ​

Forget every kept request.

tiffin dumps clear

tiffin dumps curl ​

A request as a curl command (a POSIX shell's), with its cookies and body.

tiffin dumps curl <request>

tiffin dumps replay ​

Send a request again, as it arrived: method, URL, headers and body.

tiffin dumps replay <request> [flags]

Sends a request Tiffin's proxy kept (the newest 50, in memory) to its site again, with the same cookies, headers and body, and says what came back. Its dumps and queries arrive as a new request. With --profile, Xdebug profiles it (tiffin php xdebug profile first); tiffin php profiles show <its id> reads it.

Flag
--profilewith Xdebug's trigger, so the replay is profiled

tiffin dumps show ​

A request's dumps and queries, in order (an id or its start).

tiffin dumps show <request>

tiffin elevate ​

Set the system up for Tiffin once (asks for your password).

tiffin elevate [flags]

Trust Tiffin's CA (for HTTPS on .test only), send .test names to tiffind and, on Linux, let tiffind use ports 53, 80 and 443. On Linux it also, when needed, stops another local tool's system services that hold the ports, repairs /etc/systemd/resolved.conf.d if it is not root's, and installs certutil for Chrome; it lists each step first. It asks for your password (sudo) or for permission (Windows) once; nothing else in Tiffin needs it afterwards.

Flag
-y, --yesdo not ask before changing the system (the password or UAC prompt still appears)

tiffin env ​

tiffin env [site]

Prints APP_URL, the database (what tiffin.toml asks for, else what runs), Redis, the mail catcher and the dumps receiver, ready to paste into .env. Nothing is written to the project.

tiffin harvest ​

tiffin harvest <url> [flags]

Fetches a web page and lists the URLs it refers to: links, styles, scripts, images, media and frames. With --save, the page and its same-host assets are saved into a folder (and up to --pages linked same-host pages), their URLs made relative.

Flag
--kind stringonly this kind: page, style, script, image, media, frame, other
--pages intwith --save, also save up to this many linked same-host pages (at most 50)
--save stringsave the page and its assets into this folder

tiffin hash-password ​

Hash a password as Laravel and PHP's password_hash do.

tiffin hash-password [flags]

Reads a password (asked for in a terminal, else the first line of stdin; never an argument, which others could see) and prints its bcrypt hash ($2y$, cost 12 like Laravel) or with --argon2id PHP's argon2id hash. --verify checks the password against a hash instead.

Flag
--argon2idargon2id (PHP's defaults: 64 MiB, 4 passes, 1 thread) instead of bcrypt
--cost intbcrypt's cost, 4 to 20 (default 12)
--verify stringcheck the password against this hash

tiffin php ext ​

PHP's extensions: what each version has, switch shared ones, add your own.

tiffin php ext [flags]

Lists each installed PHP's extensions: built in (always on), shared (shipped beside PHP: on Windows, php.net's DLLs; switch them on or off) and your own files, added for one series. Xdebug and pcov are tiffin php xdebug and pcov.

Flag
--version stringa PHP series (8.4) or version; default: every version

tiffin php ini ​

tiffin php ini [flags]

tiffin php obfuscate ​

Strip comments and whitespace from PHP files (php -w), optionally encoded.

tiffin php obfuscate <file-or-folder> --out <folder> [flags]

Writes a copy of a .php file or a folder into --out: every .php file through php -w (comments and whitespace removed) and, with --encode, wrapped in eval(gzinflate(base64_decode(...))). Other files are copied; vendor/ and .git/ are skipped. --out must be outside the source.

This is light protection, not security: anyone with PHP can read the code back. Encoded files see FILE and DIR differently.

Flag
--dry-runonly list what would be done
--encodealso wrap each file as eval(gzinflate(base64_decode(...)))
--include-vendorprocess vendor/ too
--out stringthe output folder (required)
--php stringthe PHP version to use; default: the global one

tiffin php xdebug ​

Switch Xdebug on or off, for every PHP version or one (--version).

tiffin php xdebug [on|off|coverage|profile|<modes>] [flags]

Xdebug is in every PHP Tiffin installs, off until you switch it on.

on        step debugging and Xdebug's better errors (debug,develop)
coverage  code coverage for PHPUnit and Pest
profile   cachegrind profiles
off       not loaded at all: no slowdown

or Xdebug's own modes, comma-separated (debug,trace). Your IDE listens on port 9003; a request starts a session when it asks (XDEBUG_TRIGGER, or a browser extension). Sites and the command line both get it; running PHP restarts. With no argument, shows what each PHP version has.

bash
  tiffin php xdebug on
  tiffin php xdebug coverage --version 8.4
  tiffin php xdebug off
Flag
--version stringa PHP series (8.4) or version; default: every version

tiffin route ​

A site's routing rules: paths with no file go to a script or page.

A routing rule sends the paths under a prefix that match no real file or folder to a target in the web root: a nested front controller (tiffin route add portal /api api/index.php) or a single-page app's shell (tiffin route add dashboard / index.html). Real files always win; the longest prefix applies. A PHP target takes every method, a page only GET and HEAD.

tiffin run ​

Run a file or a snippet with a runtime Tiffin installed (the code playground).

tiffin run [<file> | -] [flags]

Runs code with PHP, Node.js, Python, Ruby, Go, Bun or Deno, as the app's code playground does: tiffind starts the runtime's own program, with a time limit, and its output streams here. The code comes from a file, from -e, or from standard input (a file of -, or a pipe).

The language comes from the file's extension, or from --lang, which can also pick a version: --lang php@8.3. Without a version, the global one runs. The code runs in the current folder (or --dir), from a copy, so relative paths work but DIR and FILE name a temporary file. --laravel runs it in a Laravel project with php artisan tinker.

tiffin run exits with the program's own exit code; 124 if it ran out of time, 130 if you pressed Ctrl+C. With --json, the output comes back as one object when the program ends.

tiffin run script.php
tiffin run -e 'echo PHP_VERSION;' --lang php@8.3
tiffin run --laravel -e 'User::count()'
echo 'console.log(1 + 1)' | tiffin run --lang node
Flag
-e, --code stringthe code to run, instead of a file
--dir stringthe folder to run in (default: the current folder)
-l, --lang stringthe language, optionally with a version: php, node, python, ruby, go, bun, deno; php@8.3
--laravelrun in a Laravel project (--dir) with php artisan tinker
--listlist the languages and the versions installed
--timeout durationstop the program after this long (at most 5m) (default 30s)

tiffin self-update ​

Update Tiffin to the newest release.

tiffin self-update [flags]

Check Tiffin's releases now and install a newer one: the Windows installer, the macOS app or the archive you unpacked are replaced, then tiffind restarts. A Linux .deb or .rpm is downloaded and checked, then installed with your password (sudo), and tiffind restarts. Installed with Homebrew or Scoop? It says that one's command. -y, --yesdo not ask before installing a Linux package (the password prompt still appears)

tiffin tunnel ​

Serve sites on your own domain through a named Cloudflare tunnel.

tiffin tunnel

A named tunnel serves sites at hostnames on a domain of yours on Cloudflare, such as https://shop.example.com, the same address every time. It needs a Cloudflare account (free) with the domain on it:

tiffin tunnel create                       create the tunnel on the account
tiffin tunnel route shop shop.example.com  serve shop.test at shop.example.com
tiffin tunnel up                           start serving (until down, or tiffind stops)
