What tiffin elevate changes

On this page

What tiffin elevate changes ​

tiffin elevate sets your computer up for Tiffin, once. It shows the steps first, then asks for your password (an administrator prompt on Windows) and hands them to tiffin-helper, the only part of Tiffin that ever runs with those rights. The helper does one step per run, takes no input but its own typed arguments, uses no network, and checks it was installed where only an administrator can change it.

tiffin unelevate undoes every step, removing only what Tiffin added.

Trust Tiffin's certificate authority ​

Tiffin makes its own certificate authority, on your computer, for your sites' HTTPS. It is limited to .test and localhost names and loopback addresses, so it can't vouch for any other site.

macOSadded to the System keychain, trusted for SSL
Windowsadded to the computer's Trusted Root store, for server authentication
Linuxadded to your distribution's certificate bundle; on Linux, also to Firefox's policy

Send .test names to Tiffin ​

Only .test names; every other lookup is untouched.

macOS/etc/resolver/test points at tiffind (127.0.0.1:1053)
Windowsa .test rule in the DNS client's name resolution policy; where Group Policy controls those rules, your sites are listed in the hosts file instead
Linuxa systemd-resolved drop-in, resolved.conf.d/tiffin.conf (Domains=~test)

Let tiffind use ports 53, 80 and 443 (Linux) ​

A capability on the tiffind program itself (cap_net_bind_service), not a system-wide setting, so no other program gains anything. The Linux packages give it back after each upgrade. macOS and Windows need no such step.

Fix what is in the way (Linux, only when needed) ​

tiffin elevate lists each of these before it asks for your password, and adds a step only if it applies:

  • Stop and disable another local tool's system services that run or start at boot and hold ports 80 and 443. Their files stay, so you can turn them back on. Tiffin restarts itself afterwards to take the ports.
  • Make /etc/systemd/resolved.conf.d root's own (chown root:root, chmod go-w) when another user owns it or can write to it. Tiffin will not put the .test setting into a folder someone else can change. It changes only that folder, and only if every folder above it is already root's.
  • Install certutil (libnss3-tools or nss-tools) with apt-get, dnf, pacman or zypper, so Chrome and Chromium can trust the CA. The package manager downloads it. With none of these, Tiffin tells you which package to install.

tiffin doctor --fix runs tiffin elevate for these, then installs PHP (tiffin add php) if none is installed.

Install the helper (when needed) ​

When the helper isn't already somewhere only an administrator can change (a package puts it there), tiffin elevate copies it to /usr/local/libexec/tiffin or Program Files\Tiffin first.
