tiffin.toml ​

A project's tiffin.toml, committed with its code, says what the project needs. tiffin up, run in the project folder or any subfolder, brings it all up:

  1. it installs what's missing;
  2. it starts the services;
  3. it creates the databases;
  4. it serves the site.

Running it again changes nothing and needs no network once everything is installed (ADR 0034).

toml
[runtimes]
php = "8.4"     # versions on PATH in this folder (through the shims)
node = "22"

[services]
postgres = { version = "18", port = 5433, databases = ["shop", "shop_test"] }
valkey = "9"    # a string is just the version; "redis" also means valkey
minio = {}      # "minio" means silo, the maintained MinIO fork

[site]
name = "shop"   # serves shop.test; or domain = "shop.test"; default: the folder's name
https = true    # redirect http:// to https://
aliases = ["store"]  # store.test serves it too
root = "web"    # the folder to serve; default: detected (public/ for Laravel)

[site.routes]   # paths with no file under a prefix go to a target in the web root
"/api" = "api/index.php"

[processes]     # kept running by tiffind, in this folder
queue = "php artisan queue:work"
vite = "npm run dev"

[runtimes] ​

Package name = version spec. "8.4" means the newest 8.4.x; "" means the default version. The shims use these pins for every command run in this folder or below (ADR 0013), and sites use the PHP pin (ADR 0021). tiffin up installs a matching version if none is installed. It doesn't change your global default.

[services] ​

Package name = a version spec, or a table:

KeyMeaning
versionversion spec, as for runtimes (default: the default version)
port1024-65535 (default: the port it last used, else its usual one)
databasesnames to create: lowercase letters, digits and _, starting with a letter

An instance is shared by every project that uses the same major version (postgres@18), so two projects that both name postgres = "18" share one server. Give a project its own port only if it needs its own server for another major version. tiffin service stop stops an instance.

How to connect:

  • MySQL and MariaDB: user root, no password.
  • PostgreSQL: user postgres, no password.
  • All of them are on 127.0.0.1 only.

[site] ​

Serves the project folder as <name>.test. The web root (public/) is detected as for tiffin link. If the name already serves another folder, tiffin up stops and says which.

  • https = true turns redirects to HTTPS on.
  • https = false leaves the setting as it is.
  • aliases = ["store", "admin"] gives the site more names: store.test serves it too. An alias that already serves the folder is left alone; one serving another folder stops tiffin up. Removing a name from the list doesn't remove the alias (tiffin unalias store does).
  • root = "web" serves that folder of the project instead of the detected one ("." for the project itself), as tiffin root does.
  • [site.routes] maps URL prefixes to files in the web root, as tiffin route add does. tiffin up adds the rules the site lacks; it never removes one.
  • Every name under the site or an alias serves it too: api.shop.test, {tenant}.shop.test.

[processes] ​

Name = command: the commands tiffind keeps running for the project (tiffin up and tiffin proc start start them). Names are lower-case letters, digits and -. A command is split into arguments with "…" and '…' quoting, and run without a shell in the project folder, with Tiffin's shims first on PATH; &&, |, ;, <, > and line breaks are refused, and a backslash escapes nothing (Windows paths stay as written). On Windows a .cmd or .bat (npm) runs through cmd.exe, so its arguments can't hold " % ^ & | < > ( ) !.

Checking ​

Unknown keys, wrong types and bad names are errors with their path (services.postgres.port: must be a number between 1024 and 65535), so a typo never goes unnoticed. The shims read only [runtimes].
